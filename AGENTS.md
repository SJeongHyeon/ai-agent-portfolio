# Portfolio Project Instructions

## Purpose

- The primary reader is a recruiter or technical interviewer hiring a junior AI agent developer.
- Optimize for truthful evidence, clear reasoning, and reproducible work.
- Keep the positioning focused on reliable AI systems with a growth path toward voice and multimodal interaction.

## Working Mode

- Explain changes in Korean and retain standard English technical terms.
- When a decision changes positioning, public claims, repository structure, or deployment, ask one focused question before changing it.
- For routine implementation, state safe assumptions and continue without unnecessary interruptions.
- Teach the user the GitHub-to-Vercel flow as each step is completed.

## Engineering Rules

- Prefer the smallest implementation that satisfies the current portfolio goal.
- Keep content data in `src/portfolio.js`, DOM setup in `src/main.js`, layout in `index.html`, and presentation in `styles.css`.
- Do not add a framework, production dependency, analytics service, form backend, or AI chatbot without an explicit request and a verified need.
- Write or update a failing test before changing behavior.
- Run `npm test` after changes.
- Do not claim expert, production-ready, scalable, or improved performance without evidence.

## Public Repository Safety

- Never commit API keys, tokens, `.env` files, private logs, personal chat records, or real user data.
- Do not publish personal contact details unless the user explicitly provides and approves them.
- Preserve the existing `Streamlit`, `MINI-TEST`, and Vercel projects until the new deployment is verified.
- Commit, push, repository creation, domain movement, and Vercel configuration changes require explicit user authorization.

## Portfolio Evidence

- Label completed work `Built`, current implementation `Building`, and future study `Exploring`.
- Every Built project needs a public code or demo link and at least one verifiable artifact.
- Explain problem, approach, evidence, limitation, and next improvement.
- Prefer one strong representative project over many shallow project cards.
